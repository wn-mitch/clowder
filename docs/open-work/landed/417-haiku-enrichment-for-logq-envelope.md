## Why

`just q` (logq) is the workhorse drill-down tool for any sim-run
investigation. Every envelope ends with a `next` field meant to seed the
agent's next query, but today that field is generated by **pattern-blind
heuristics**: `cmd_deaths` always suggests `cat-timeline` for the
most-common-cat-in-results regardless of whether that cat is interesting;
`cmd_run_summary` always suggests `actions` whether or not actions are
the signal-bearing slice; no subtool reads the assembled `narrative` or
ranks by signal density.

A cheap Haiku call (subscription-billed, ~$0.001-0.002/call) that reads
the already-assembled envelope (`narrative` + top results + `query`)
produces **ranked, annotated** suggestions plus a 1-2 sentence
pattern-recognition `hint`. This raises the floor on every investigation
without changing the existing contract. It also establishes a small
shared `claude` CLI client that tickets **010** (post-death biographies)
and **011** (cat-conversation rendering via Haiku) will reuse when they
ship — both currently spec a strict-presenter LLM integration but have
no infrastructure yet.

## Scope

- New module `scripts/llm/claude_client.py` — thin subprocess wrapper
  around the `claude --bare --print` CLI; returns `(parsed_json | None,
  meta)`; never raises.
- New prompt + schema under `scripts/llm/prompts/logq_enrich.{md,schema.json}`.
- Extend `Envelope` dataclass at `scripts/logq/envelope.py:29-35` with two
  optional fields: `hint: str | None` and `next_reasoned: dict | None`.
  Render in `to_text()`. Existing `next` field **never mutated**.
- Single enrichment hook in `scripts/logq/logq.py::main()` between
  envelope-build (`:1730`) and emit (`:1742`). Gated by `LOGQ_ENRICH=1`
  env var and/or `--enrich/--no-enrich/--enrich-timeout` CLI flags.
  Initial subtool set: `{run-summary, deaths, anomalies, cat-timeline,
  narrative}`.
- Determinism CI audit test analogous to ticket 010's
  `rm -rf logs/biographies && just soak` invariant: stripping `hint`
  and `next_reasoned` from the enriched output yields the un-enriched
  output byte-for-byte.
- Failure-mode contract: timeout / nonzero / malformed / disabled /
  exception all surface as a `next_reasoned.status` discriminator; the
  deterministic `next` field stays valid.
- `append_call_history` at `:1739` records `enrichment_status` and
  `enrichment_elapsed_ms` so post-hoc analysis can audit which calls
  Haiku helped vs failed silently.

## Out of scope

- Live API key (`ANTHROPIC_API_KEY`) path — billing must go through the
  user's `claude` CLI subscription, full stop.
- Enrichment for `footer` / `events` / `actions` / `hunt-success` / `trace`
  subtools — large/repetitive or already-structured; add after a week of
  usage if proven valuable.
- Default-on behavior — first ship is opt-in; default flips after a
  week of self-use via a `logs/.logq-enrich-on` sentinel file.
- Refactoring tickets 010/011 to consume the new client — those tickets
  stay blocked/future; this ships the client preemptively, but the
  signature is already general enough that no rework is needed when
  010 lands.

## Approach

Two commits in this PR:

1. **client + prompts + unit tests** — `scripts/llm/` + `tests/llm/`,
   with mocked subprocess only.
2. **logq integration + envelope fields + CI audit test** — modifies
   `scripts/logq/envelope.py`, `scripts/logq/logq.py`,
   `tests/logq/test_envelope.py`.

**Strict-presenter discipline** (from ticket 010): the LLM never feeds
into sim state, never mutates the existing `next` field, only adds two
new optional fields that are absent when enrichment is off or fails. CI
audit test enforces.

**Defensive client design**:
- `--bare` mode skips hooks/LSP/plugin-sync/auto-memory/CLAUDE.md
  discovery — fast and side-effect-free.
- Schema enforcement in-prompt + post-validate in Python (don't depend
  on the `--json-schema` CLI flag's stability across versions).
- Single retry on `timeout` only. `nonzero` is auth/config and won't
  fix itself.
- Defensive stdout parsing tolerates CLI preamble lines.
- Gate enrichment off when `CLAUDE_SESSION_ID` is set — avoids nested
  `claude --bare` calls from a polecat-child `just q` invocation
  interfering with the parent session.
- Truncate envelope payloads past ~8KB with a truncation note so the
  model knows it's seeing a sample.

## Verification

1. **Unit tests** in `tests/llm/test_claude_client.py` and
   `tests/logq/test_envelope.py` — all mocked, no live network.
2. **Determinism CI audit test**:
   `LOGQ_ENRICH=0 just q ... ≡ (LOGQ_ENRICH=1 just q ... minus enrichment fields)`
   — byte-identical.
3. **Manual smoke**: `LOGQ_ENRICH=1 just q anomalies logs/tuned-42`
   (and `run-summary`, `deaths`) against a recent run; inspect `hint`
   and `next_reasoned.suggestions`; verify the suggested cmds parse and
   return non-empty envelopes.
4. **Latency budget**: 10 timed calls, assert p95 < 5s; if not, lower
   default timeout or move enrichment behind `--enrich` only.
5. **Determinism diff**:
   `diff <(just q run-summary L) <(LOGQ_ENRICH=0 just q run-summary L)`
   → empty.
6. **Cost ballpark** after one week of self-use — should be
   subscription-noise.
